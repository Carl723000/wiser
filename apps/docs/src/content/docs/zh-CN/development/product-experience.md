## 这份文档约束什么

本指南约束 `apps/web` 中用户能够看到和操作的产品表面。视觉 Token、字体、主题和组件语义见 [WISER Design System](/architecture/design-system/)；路由、Server Component、数据访问和 Playwright 流程见[前端开发](/development/frontend/)。

产品界面不是开发文档、架构图或运行手册。它首先帮助使用者回答：

1. 我现在位于平台的哪一层？
2. 我能完成什么任务？
3. 当前状态对我的工作有什么影响？
4. 下一步可以做什么？

实现原理、内部服务、配置项和排障步骤进入文档、日志或受控运维工具，不进入普通业务页面。

## 固定的信息层级

所有系统使用同一条层级，不得混排：

```text
WISER Portal
  → 业务系统
    → 系统工作区
      → 领域对象与对象内页签
```

| 层级       | 作用                                          | 当前示例                               |
| ---------- | --------------------------------------------- | -------------------------------------- |
| Portal     | 说明 WISER 是什么、有哪些系统，并引导统一登录 | `/zh-CN`、`/en`                        |
| 业务系统   | 在平级业务边界之间切换                        | 数据基座、智能体演练场                 |
| 系统工作区 | 完成该系统内的稳定任务                        | 数据目录、数据接入；演练场景、演练运行 |
| 领域对象   | 查看或操作一个具体 DataItem、场景、Run 或任务 | Run 总览 / 协作 / 评测 / 追踪 / 回放   |

约束如下：

- WISER Logo 永远返回当前语言的 Portal；Portal 不是第三个业务系统。
- 一级系统导航固定把基础能力“数据基座”放在“智能体演练场”之前。
- Portal 和登录页不显示任何系统二级导航。
- 二级导航只在进入对应系统后显示；对象内页签不得提升为平台导航。
- 新系统只能加入一级系统列表，不能新建平行 Header、身份入口或主题控制。

## 产品命名

| 概念               | 中文产品名   | 英文产品名      | 说明                         |
| ------------------ | ------------ | --------------- | ---------------------------- |
| 平台               | WISER        | WISER           | 不翻译、不作为系统标签       |
| Data Foundation    | 数据基座     | Data Foundation | 一级业务系统，排在第一位     |
| Agent EXCON        | 智能体演练场 | Agent EXCON     | 中文界面不直接显示英文品牌名 |
| Scenario workspace | 演练场景     | Scenarios       | 智能体演练场二级任务         |
| Run workspace      | 演练运行     | Exercise runs   | 智能体演练场二级任务         |

协议名、代码标识符和产品展示名分开维护。URL、DTO、数据库字段可继续使用稳定英文标识；用户可见标题按上表表达。

## 公开入口与登录边界

- `/` 重定向到中文 Portal `/zh-CN`；`/en` 提供同构英文 Portal。
- Portal、登录页与 Auth transport 路由允许匿名访问。
- 使用 Supabase Auth 的环境中，进入数据基座或智能体演练场工作区前必须拥有已验证 Session；匿名请求保留目标地址并跳转到对应语言的登录页。
- `WISER_AUTH_MODE=off` 只用于显式本机参考预览，不能作为生产身份模式。
- Portal 允许匿名使用者理解两个系统的职责，但不展示项目数据、运行数据或伪造业务指标。
- 登录页只说明组织账户、组织范围和项目权限；Supabase、Cookie、Token、publishable key 等实现说明进入开发文档。

## 产品语言

### 写作顺序

一段界面文案按需要依次回答：用户目标 → 当前状态 → 影响 → 下一步。通常一到两句已经足够。

| 使用场景 | 应该写                                          | 不应该写                                     |
| -------- | ----------------------------------------------- | -------------------------------------------- |
| 页面导语 | 用户能在这里完成什么                            | 模块采用了哪些数据库、队列、投影或 DTO       |
| 空态     | 当前没有什么，以及用户现在能做什么              | “API 尚未提供”“不使用 fixture”“不会伪造数据” |
| 失败态   | 发生了什么、工作是否受影响、可执行的恢复动作    | HTTP 状态、环境变量、内部 URL、健康检查命令  |
| 权限态   | 当前账户不能访问，以及向谁申请                  | Role/Scope/Tenant 校验链路                   |
| 专业详情 | 完成任务确实需要的 Trace、Span、CRS、版本和哈希 | 与当前任务无关的基础设施细节                 |

普通产品页面禁止出现：

- 环境变量名、凭据名、内部主机名和内部 URL；
- HTTP 401/403/5xx、原始错误码或上游响应正文；
- DTO、DAL、Capability Registry、Worker、Outbox 等实现词；
- “参考样例没有补齐”“接口尚未覆盖”等开发过程叙事；
- 要求普通用户检查数据库、对象存储、日志或健康端点的恢复步骤。

如支持团队需要关联问题，只显示无敏感信息的支持编号；技术原因写入服务端日志。

## 状态组件合同

- 空态说明当前范围，并提供一个可执行动作；没有动作时说明何时或由谁补充。
- 失败态由简短标题、影响说明、恢复建议和主操作组成；`role="alert"` 只播报这些用户信息。
- 同一动作从按钮、进行中状态到完成提示保持同名。
- 状态同时使用文字与形状，不能只依赖颜色。
- 原始协议 code 只在专业详情按需显示，不与每个状态标签重复。
- 不得为了页面“看起来有数据”而把示例、缓存或推断值混入实时业务状态。

## 国际化与实现

- 所有可见文案进入 `apps/web/src/lib/i18n.ts` 的同构字典；组件内不得散落 `locale === ...` 的双语文案分支。
- 中文先按自然、专业的人类表达完成，再写语义等价的英文；英文不能多出或缺少事实、状态或操作。
- 第三方控件的可访问名称也必须由字典显式提供，不能依赖浏览器或库的默认语言。
- 导航顺序和路径判断集中在纯配置/函数中；页面组件不得用“不是数据基座就当作演练场”一类隐式分支。
- 失败原因可以在服务端分类，但浏览器只接收安全的产品文案和必要的支持编号。

## 新系统接入清单

1. 在一级系统配置中加入唯一 ID、稳定入口和双语产品名，并说明其与既有系统平级的业务职责。
2. 复用 Portal、Header、统一登录、主题、语言和 Footer，不创建第二套平台外壳。
3. 为系统定义少量、任务导向的二级工作区；对象内页签留在对象页面。
4. 同时补齐中文和英文 Portal 说明、导航、页面、空态、失败态与权限态。
5. 确认匿名只能看到适合公开的系统介绍；项目内容经过统一 Session 和系统授权。
6. 增加纯导航测试和 Playwright：Portal、两种语言、两种主题、桌面、390px、键盘、reduced motion、登录 continuation 与技术信息不泄露。

## 验收

每项产品界面改动至少验证：

- Portal → 系统 → 工作区 → 对象层级清楚，且没有重复或倒置导航；
- 中文没有未约定的英文产品名，英文没有遗漏的中文叙述；
- 页面首屏不包含环境变量、内部 URL、HTTP 状态或开发恢复步骤；
- 深浅色、桌面与 390px 无横向溢出，主操作无需 hover；
- Skip link、一级/二级导航、主题、语言和主操作可由键盘到达；
- reduced motion 下没有必要之外的动画；
- 普通失败态不泄露服务器秘密或原始响应。

## 当前用户路径

| 路径         | 首先看到什么                       | 下一步可执行操作                                         |
| ------------ | ---------------------------------- | -------------------------------------------------------- |
| 门户与登录   | 两个业务系统和一套组织账户         | 登录后进入有权限的项目                                   |
| 数据基座     | 带当前项目范围的查询与探索工作区   | 选择资料，核对固定版本，再查看记录、地图、关系或统计     |
| 数据接入     | 任务编号以及检查、审核和发布状态   | 用智能体给出的编号打开任务；处理明确指出的问题或等待审核 |
| 权限管理     | 当前成员和资料访问，与历史申请分开 | 申请访问；有管理资格时复核并执行授权                     |
| 智能体演练场 | 场景与运行状态，以及团队协作和评测 | 打开一次运行，查看成果交接、评测、追踪或回放             |

使用者应能区分原件内容、质量检查、发布状态和访问权限。“解析内容记录数”表示已索引内容，不等于去重后的独立观测。地图能显示几何不等于位置已经核准，来源、生成方式、时间和适用尺度应随结果可见。关系保留来源与审核状态，待审候选不会被表述为已通过知识。

空态说明当前范围并给出真实可执行的操作；失败态说明影响、已有工作是否保留，以及重试或联系管理员的路径。权限拒绝指出项目或资料范围，不显示内部策略代码。按钮、办理中和完成反馈使用相同的动作名称。

专业行为与固定版本查询契约见[数据基座架构](/architecture/data-foundation/)和 [Data REST 协议](/protocols/data-rest/)；路由结构、会话授权读取及浏览器验证见[前端开发](/development/frontend/)。这些技术参考可以使用协议术语，普通工作区仍遵循以上文案规则。

本机空间资料工作台先选区域与时期，再查看真实来源、原文定位和就绪情况。档案先解释位置角色与内容，再提供固定版本回查；行政参考范围不称为精确河段。候选演练有独立标识与退出操作，演练决定不能呈现为专业批准。矩阵需求位置是规划用途，不是已收到的数据套数。

数值比较分别核对原值和计算结果。原值不可计算或相减结果超出有限数值范围时，保留并排查证及原值，差值为空并显示阻断原因；有效0值和0差值不当作缺失。

比较还须阻断带空白的未知单位，以及原日期不足声明年／月／日精度的情况。单位原文保持不变，不自动换算或认定等价；普通日期筛选仍可展开日历范围，但展开结果不能补足比较所缺的精度。这些检查不能代替位置可比性核验或专业批准。

本机比较的位置守卫要求每条观测只有一个采样／统计支持位置声明，具有显示许可、原文定位和相同的固定几何来源／版本、几何及尺度说明。空白或明确写为“未知”／`unknown`的尺度说明均被拒绝，包括周围带空白的情况；原文不改写。未决的额外采样声明在显示过滤前阻断比较。行政参考范围或研究区不能替代采样证据；相同线面几何不能证明聚合粒度。河段或区域仅在固定定义明确其统计支持、聚合规则与实际分母时进入数值准入，点位也须有明确计量定义。

连续量、有序类别、编码和未知分别声明；明确等级编码仍不相减。来源声明不代替独立专业复核，数值形式或指标名称不作为连续量的正向证据。定义、指标、方法、单位、原生时间口径、统计粒度、分母或固定版本不足时，保留原值和并列查阅并显示原因。来源、记录和定义的真实／合成轨道分别核对；本机包只支持标明演练的合成批准正例，真实待审记录不计算差值。

本机保存场景沿用固定来源清单纳入所引用的定义来源。定义来源撤回或版本／哈希／处理版本改变后，计算失效，原记录仍可并列查证；已有原件和历史不删除。上述契约和本机规则验证不代表标准候选持久化、真实审核、服务端权限或浏览器端到端验收完成。

本机版本影响计算在几何加工规则改变时，纳入明确引用该几何来源与固定版本的记录。月报记录自身的解析规则版本不能代表所引用几何的加工规则；所有匹配引用进入复核范围，无关来源与版本仍排除。该计算不修改记录、不重算结果，也不替代持久依赖或浏览器验收。

地图选择保留资料内的具体位置身份。同一记录的其他位置不随之高亮；没有所选位置的记录仍可在档案中阅读。

窄屏空间查阅采用“地图、结果、证据”标签，不压缩桌面各列。区域使用紧凑选择框，筛选默认收起。切换保留范围、具体记录与位置、来源版本、地图视角及已加载结果；选择证据与位置定位分别进入对应区域。撤回证据同时从可见区和仍挂载的隐藏区移除。本机查阅能力不能作为真实鉴权、接收、审核或发布通过的证明。

定位或复位后的镜头在查看证据、改变屏幕尺寸和退出全屏后仍保持有效。重新打开所选资料保留已选的可显示具体位置及固定几何依据，不悄然改选第一位置。

证据查阅先呈现原值、来源、时间、审核状态及可执行的原文入口。完整技术标识进入有名称、可用键盘展开的详情；缺项和参考位置限制保持可见。身份解释复用情境帮助，来源撤回同时移除可见内容与已展开的技术依据。

地图图例仅说明当前显示的资料类别与位置角色。参考几何在选中后仍保留虚线边界或空心点，适用范围使用点线。所选具体位置保留原文表达和尺度说明；重叠选择显示可读来源与位置名称，固定标识进入默认收起的技术详情。撤回或更换版本的位置退出选择列表。此显示不生成几何、不合并对象、不解决候选，也不批准位置精度。

就绪九问先打开对应类型的事实，再由读者选择记录或固定来源，不隐式跳到第一条。数量卡片区分计数粒度，未登记任务和责任人保留明确状态；有依据不等于专业批准。月份输入将已生效核对条件与尚未提交的编辑分开。待审河名对应提供标识清楚的假设统计，不合并身份或修改原始计数。

空间结果分别以已定位、位置未确定、范围外三组分页表格查阅，每页最多40条。原生时间范围、精度与角色、原值与单位、来源及提供单位、审核状态和可显示位置依据分别列示。地图、证据和全屏往返保留阅读页及精确选择；结果范围改变后重置页码。表格在有界面板内滚动，支持键盘，窄屏固定对象列。撤回记录从已挂载结果中移除，未知字段与有效零值分开保留。

## 这份文档约束什么

本指南约束 `apps/web` 中用户能够看到和操作的产品表面。视觉 Token、字体、主题和组件语义见 [WISER Design System](/architecture/design-system/)；路由、Server Component、数据访问和 Playwright 流程见[前端开发](/development/frontend/)。

产品界面不是开发文档、架构图或运行手册。它首先帮助使用者回答：

1. 我现在位于平台的哪一层？
2. 我能完成什么任务？
3. 当前状态对我的工作有什么影响？
4. 下一步可以做什么？

实现原理、内部服务、配置项和排障步骤进入文档、日志或受控运维工具，不进入普通业务页面。

## 固定的信息层级

所有系统使用同一条层级，不得混排：

```text
WISER Portal
  → 业务系统
    → 系统工作区
      → 领域对象与对象内页签
```

| 层级       | 作用                                          | 当前示例                               |
| ---------- | --------------------------------------------- | -------------------------------------- |
| Portal     | 说明 WISER 是什么、有哪些系统，并引导统一登录 | `/zh-CN`、`/en`                        |
| 业务系统   | 在平级业务边界之间切换                        | 数据基座、智能体演练场                 |
| 系统工作区 | 完成该系统内的稳定任务                        | 数据目录、数据接入；演练场景、演练运行 |
| 领域对象   | 查看或操作一个具体 DataItem、场景、Run 或任务 | Run 总览 / 协作 / 评测 / 追踪 / 回放   |

约束如下：

- WISER Logo 永远返回当前语言的 Portal；Portal 不是第三个业务系统。
- 一级系统导航固定把基础能力“数据基座”放在“智能体演练场”之前。
- Portal 和登录页不显示任何系统二级导航。
- 二级导航只在进入对应系统后显示；对象内页签不得提升为平台导航。
- 新系统只能加入一级系统列表，不能新建平行 Header、身份入口或主题控制。

| 概念               | 中文产品名   | 英文产品名      | 说明                         |
| ------------------ | ------------ | --------------- | ---------------------------- |
| 平台               | WISER        | WISER           | 不翻译、不作为系统标签       |
| Data Foundation    | 数据基座     | Data Foundation | 一级业务系统，排在第一位     |
| Agent EXCON        | 智能体演练场 | Agent EXCON     | 中文界面不直接显示英文品牌名 |
| Scenario workspace | 演练场景     | Scenarios       | 智能体演练场二级任务         |
| Run workspace      | 演练运行     | Exercise runs   | 智能体演练场二级任务         |

协议名、代码标识符和产品展示名分开维护。URL、DTO、数据库字段可继续使用稳定英文标识；用户可见标题按上表表达。

## 公开入口与登录边界

- `/` 重定向到中文 Portal `/zh-CN`；`/en` 提供同构英文 Portal。
- Portal、登录页与 Auth transport 路由允许匿名访问。
- 使用 Supabase Auth 的环境中，进入数据基座或智能体演练场工作区前必须拥有已验证 Session；匿名请求保留目标地址并跳转到对应语言的登录页。
- `WISER_AUTH_MODE=off` 只用于显式本机参考预览，不能作为生产身份模式。
- Portal 允许匿名使用者理解两个系统的职责，但不展示项目数据、运行数据或伪造业务指标。
- 登录页只说明组织账户、组织范围和项目权限；Supabase、Cookie、Token、publishable key 等实现说明进入开发文档。

## 产品语言

### 写作顺序

一段界面文案按需要依次回答：用户目标 → 当前状态 → 影响 → 下一步。通常一到两句已经足够。

| 使用场景 | 应该写                                          | 不应该写                                     |
| -------- | ----------------------------------------------- | -------------------------------------------- |
| 页面导语 | 用户能在这里完成什么                            | 模块采用了哪些数据库、队列、投影或 DTO       |
| 空态     | 当前没有什么，以及用户现在能做什么              | “API 尚未提供”“不使用 fixture”“不会伪造数据” |
| 失败态   | 发生了什么、工作是否受影响、可执行的恢复动作    | HTTP 状态、环境变量、内部 URL、健康检查命令  |
| 权限态   | 当前账户不能访问，以及向谁申请                  | Role/Scope/Tenant 校验链路                   |
| 专业详情 | 完成任务确实需要的 Trace、Span、CRS、版本和哈希 | 与当前任务无关的基础设施细节                 |

普通产品页面禁止出现：

- 环境变量名、凭据名、内部主机名和内部 URL；
- HTTP 401/403/5xx、原始错误码或上游响应正文；
- DTO、DAL、Capability Registry、Worker、Outbox 等实现词；
- “参考样例没有补齐”“接口尚未覆盖”等开发过程叙事；
- 要求普通用户检查数据库、对象存储、日志或健康端点的恢复步骤。

如支持团队需要关联问题，只显示无敏感信息的支持编号；技术原因写入服务端日志。

## 状态组件合同

- 空态说明当前范围，并提供一个可执行动作；没有动作时说明何时或由谁补充。
- 失败态由简短标题、影响说明、恢复建议和主操作组成；`role="alert"` 只播报这些用户信息。
- 同一动作从按钮、进行中状态到完成提示保持同名。
- 状态同时使用文字与形状，不能只依赖颜色。
- 原始协议 code 只在专业详情按需显示，不与每个状态标签重复。
- 不得为了页面“看起来有数据”而把示例、缓存或推断值混入实时业务状态。

## 国际化与实现

- 所有可见文案进入 `apps/web/src/lib/i18n.ts` 的同构字典；组件内不得散落 `locale === ...` 的双语文案分支。
- 中文先按自然、专业的人类表达完成，再写语义等价的英文；英文不能多出或缺少事实、状态或操作。
- 第三方控件的可访问名称也必须由字典显式提供，不能依赖浏览器或库的默认语言。
- 导航顺序和路径判断集中在纯配置/函数中；页面组件不得用“不是数据基座就当作演练场”一类隐式分支。
- 失败原因可以在服务端分类，但浏览器只接收安全的产品文案和必要的支持编号。

## 新系统接入清单

1. 在一级系统配置中加入唯一 ID、稳定入口和双语产品名，并说明其与既有系统平级的业务职责。
2. 复用 Portal、Header、统一登录、主题、语言和 Footer，不创建第二套平台外壳。
3. 为系统定义少量、任务导向的二级工作区；对象内页签留在对象页面。
4. 同时补齐中文和英文 Portal 说明、导航、页面、空态、失败态与权限态。
5. 确认匿名只能看到适合公开的系统介绍；项目内容经过统一 Session 和系统授权。
6. 增加纯导航测试和 Playwright：Portal、两种语言、两种主题、桌面、390px、键盘、reduced motion、登录 continuation 与技术信息不泄露。

## 验收

每项产品界面改动至少验证：

- Portal → 系统 → 工作区 → 对象层级清楚，且没有重复或倒置导航；
- 中文没有未约定的英文产品名，英文没有遗漏的中文叙述；
- 页面首屏不包含环境变量、内部 URL、HTTP 状态或开发恢复步骤；
- 深浅色、桌面与 390px 无横向溢出，主操作无需 hover；
- Skip link、一级/二级导航、主题、语言和主操作可由键盘到达；
- reduced motion 下没有必要之外的动画；
- 普通失败态不泄露服务器秘密或原始响应。

`/[locale]/data-foundation/explore` 工作区与 API 共享严格探索契约。紧凑查询栏、资源表格与选择详情面板将结果区置于页面上方。服务端渲染建立或恢复授权结果集，后续请求经过验证当前 Session 的 Next.js 入口 `/api/data-foundation/explore`。调整筛选建立新版本清单，分页沿用同一 `queryId`。数据名称支持键盘操作，详情显示精确版本、就绪状态及来源限制；未知分析数量不会显示为零。

先展示资源就绪状态，再进入分析内容。记录视图保留原始字段名，提供有界分页、来源文件与哈希，不推断单位。地图选择在详情面板中保留版本与源记录，并明确显示当前已加载要素数和空间结果总数。

地图状态区分显示坐标转换与独立位置核对。探索地图持续说明可上图不证明位置准确，放大不会提高原始数据精度；精细使用前需核对来源、生成方式、时间及适用尺度，不再统一标为已对齐。

专业地图在所选栅格缺少要素和 STAC 范围时，也应打开已填写的查询区域。底图就绪、原文件可读、栅格正确对齐分别验收；仅看到像元，不能证明叠加完整或位置正确。

探索摘要、资源表格及详情面板将已索引总量标为“解析内容记录数”，来源文件内容使用同一计数名称。探索与资源内容页说明数量按文件累计，可能包含 CSV/XLSX 格式副本和文档片段。当前契约没有已核验的观测计数，因此“独立业务观测数”显示“未统计／待核验”。两份各含两条解析记录的文件仍累计为四条内容记录，独立观测数量保持未知。原文件、哈希、版本与来源值保持不变。文件名、字节哈希或行数相同不能证明语义等价；已核验格式副本关系与业务去重需要另行建立覆盖业务键、指标、单位、时间、完整性及修订的治理流程。

探索契约 1.5 增加可选的地图整体 `spatial.bounds`（WGS84；空结果为 null）及 `mercatorFeatureCount`，由同一授权记录集合计算，不受分页影响。浏览器只请求一条初始记录与范围摘要，定位整个结果范围，再按视口加载同源查询瓦片。点选单要素通过 1.4 的精确记录回查获取详情，点选聚合点继续放大。地图分别标明视口要素／聚合点数与可上图记录总数。追加迁移 `0015_exploration_tile_boundaries.sql` 明确接缝点的唯一瓦片归属，防止重复计数。1.4 契约仍保留在归档中。

当响应表明授权或固定成员范围失效，或结果到达声明的过期时间时，探索工作区一并清除当前查询、选择、文件详情及已渲染视图；从后台或历史页面恢复时再次检查同一截止时间。旧查询的迟到失败不能清除新查询，被中止的请求也不能恢复旧数据。查询表单条件保留，便于重新获取当前有权查看的结果。临时地图故障卸载画布并提供重新加载，不展示上游诊断。

探索查询获得授权后，地址栏只保留归属当前用户的查询编号与白名单视图名称。提交条件新增历史记录，切换视图更新当前记录。刷新、后退与前进通过同一 HTTP 能力重新校验清单授权，恢复条件和视图，并在恢复前清除旧选择。保留框架的历史状态，不将原始筛选值或记录内容写入浏览器历史状态；查询链接不会向其他用户授予访问权。

记录探索提供可展开的条件表单，支持最多八个类型明确的比较条件、标量排序及可选的 1–32 列配置。文本编号保留前导零；空白或非有限数值不能作为数值条件提交。应用条件会创建新的单版本／文件授权查询、清除选择、新增历史记录并打开记录视图；记录、地图瓦片和记录溯源使用同一谓词。刷新后从授权查询恢复配置，清除条件则恢复该版本的记录浏览。数值比较使用来源值，不推断或换算单位。

选择资源后，统计视图提供来源记录聚合，字段控件与资源就绪状态计数分开表达。图表配有精确值表格及可通过键盘操作的分组选择。单位明确显示，未知分组不会被悄悄替换成不完整的空值条件。

图谱探索提供键盘可用的文件、证据和记录展开、邻居分页、带文字的关系开关，以及限定当前页的有向路径控件。路径高亮更新 G6 节点／边状态，不替换画布。两种语言均显示计数单位、截断状态与恢复操作；切换焦点会清除路径端点和游标。

探索工作区默认保存有名称的私人视图，支持明确选择项目分享、持久链接和创建者撤销。保存链接恢复经授权的固定查询、记录／图谱分页、所选来源、地图图层／视角及已应用的聚合配置；每次打开都会重新授权并建立新查询。导出下载一次有界 JSON 结果页，保留来源原值、准确返回／总量及完整／部分标记；地图初始记录页不代表全部已加载瓦片。尚未应用的草稿条件不会保存。

数据工作区导航将检索、知识和专业空间／图谱工具归入数据探索，原有深链接继续有效，探索工具栏提供专业入口。窄屏下只有资源表可以隐藏提供机构列；记录与聚合表在自身滚动区域内保留全部所选字段和单位。来源统计将资源就绪概况放入独立折叠区，仅在展开时挂载图表。来源层级图谱宽度小于 560 像素时由 Worker 计算纵向布局，并提供键盘可用的缩放、全图及所选节点定位控件；视角操作不使用动画。

宽度不超过 900 像素时，可通过底部按钮在非模态抽屉中查看所选来源。展开后键盘焦点进入带名称的详情区域；收起或 Escape 将焦点返回按钮，保留当前选择。取消选择时按需将焦点返回当前视图页签。桌面详情仍在侧栏中滚动。G6 内部画布图层不参与 Tab 顺序，键盘交互由有名称的视角控件和来源节点列表提供。

总览任务卡片进入统一数据探索工作区及其地图视图，并用面向用户的语言描述数据接入与审核。文档站按数据基座、智能体演练场的顺序介绍业务系统，与 Portal 保持一致。

Portal 根据已验证会话选择主操作：已登录用户进入数据工作区，匿名用户进入登录页。数据目录使用每页 25 行的游标分页及可键盘聚焦的内部滚动表格，后续页和返回第一页均保留名称条件。列表保留来源、发布、质量和安全信息，并引导结合详情中的检查范围与内容就绪状态判断。

数据基座首先提供按名称进入数据探索的入口和常用操作；正常服务状态默认收起，异常状态自动展开。智能体接入页复用已有的复制接入指令操作，并用任务名称介绍能力；数据接入保留明确的任务编号查询。质量与验收状态同时解释检查范围，来源登记通过不等于科研有效性已验证。资源进入探索的链接同时携带资源和版本标识；不完整或错误版本会失败，不能扩大查询范围。图谱与 GIS 专业空页引导进入共享探索。任务事件原文和错误码不是面向用户的安全文案契约，不直接作为普通进度提示。

知识图谱画布默认使用使用确定性初始位置、最多 160 次迭代的 ForceAtlas2 关系网络，由现有可取消 Worker 计算。键盘可操作的布局切换提供 Dagre 来源层级；只有层级布局在窄屏改变方向。两种布局均保留有界身份、选择、路径高亮和文字替代视图，独立资源的关联组在二维平面分区排布。初始概览每页显示八项资源，聚焦后的邻居页保留独立条数上限。关系文字与语义节点颜色辅助表达节点类型。

资源页先展示内容工作区，治理信息位于可展开区域。版本内文件列表、原文件下载与内容页签共用精确资源身份。表格保留来源标量值，并为已知字段提供易读标签；文档与结构化视图按需展开嵌套内容。文件预览不执行来源脚本，暂不支持的格式保留明确下载操作。探索中的资源名称直接打开内容，另设选择控件以保留当前查询内的分析操作。

资源内容提供“副本核验与业务去重”：选择两份完整解析的表格，显式配置业务键、指标、单位和时间，查看候选分组及来源引用。分别显示文件数、解析记录数、候选观测数和已核验观测数。人工核对规则与证据后，仅更新本批范围内的已核验计数，资源与目录的总体独立观测数仍为未知。表单不得从文件名猜测映射或清除冲突。模糊失败重试保留幂等键，权限拒绝清除已显示证据；中英、键盘、小屏和明暗主题保持等价。

有可路由栅格源时，进入地图即显示像元，并与资产范围框分别标注。可用键盘操作的不透明度滑块只更新现有图层，不重建来源、不重置相机。透明区域不能解释为数值零；单位与数值范围仍需回查来源说明。

业务关系可加入最多六十三份带版本的平台资料链接。待审图需明确选择显示并持续标明待审。节点保留来源身份或明确引用身份。每条关系显示来源、原文、记录性质、时间与位置角色及适用条件。来源空间入口不表示已有或已核验几何。

复制业务关系链接后，新标签页或其他浏览器可恢复已经应用的来源版本范围、审核状态、明确选择的待审预览、聚焦对象和加载页数。浏览器前进后退也恢复这些条件。链接不授予权限；范围损坏或来源无权访问时，不能偷偷扩大查询重试。继续加载关系时保留前面的图，并明确说明达到加载上限的状态。

已加载业务图中的来源记录和空间入口保留经过校验的返回信息，仅含版本身份、审核状态、聚焦对象和加载页数。探索页面改写查询地址及切换标签时保留该信息，并提供返回刚才业务关系图的入口。它表示导航来处，不声称后续每次查询的范围都相同。返回地址仅由内部资料路由生成，不授予访问权，重新打开时仍核验权限；损坏信息不生成返回入口。加载范围外的引用资料保留普通来源链接。这不表示位置已核实或不同来源已具有相同空间范围。

业务关系可按对象类型与时间筛选已加载且有权限的关系。类型匹配任一端，时间含义精确匹配。日期按原资料明确时段是否重叠判断；仅有年、月时保留原粒度，不补猜具体日期。缺失、不完整、倒置或无法识别的时段保持未知；只有明确标为观测时间的记录才可使用单一观测时间。保留未知时段的选项作用于类型及时间含义选择后的日期筛选。图谱与证据列表共用同一子集，分别显示匹配、加载与总关系数；继续加载保留此前不匹配的行，清除条件后能够恢复。严格校验的筛选状态随链接、刷新、历史及来源探索返回而恢复；不扩展权限，也不宣称来源地图与记录查询已采用相同时间条件。节点标签含本地化类型，保持各来源身份。

精确记录探索链接通过有界的`recordFocus`仅保存资源、不可变版本和记录标识。打开或历史恢复时重新鉴权，并通过既有HTTP探索接口读取该条记录；返回的三个身份必须全部一致。记录缺失、参数错误、无权访问或身份不符时明确失败，不替换成首行或放宽到整份资料。地图/表格选中与视图切换保留定位及已校验的业务图返回上下文；应用新查询条件或选择其他资源时清除旧定位。选中记录不代表坐标已经核验，也不自动建立科学对象身份或图谱到空间要素的映射，这些仍须来源证据支持。保存视图继续遵守原有选中契约，不与独立记录定位混用。

观测记录节点可用`urn:wiser:record:<recordId>`声明平台记录标识，范围限定在自身来源版本或显式引用来源。网页只对OBSERVATION节点的合法UUID绑定提供精确记录与空间内容链接，不从名称猜记录，也不给文档虚设几何。链接保留原业务图返回状态，打开时重新鉴权并核对完整记录身份。此标识是导航声明，不代表服务端已认定科学身份或通过专业审核；证据和待审状态仍保留。其他外部标识不受影响。

### 精确关系历史导航

查看更正前关系时，将明确的关系ID写入来源绑定的链接。刷新和浏览器历史恢复后重新鉴权读取该条关系，并核对来源版本与审核状态；目标无效、不可读或状态已变化时失败，不替换成其他行。历史查看清除图节点聚焦和日期筛选，保留可授权核查的案例范围，不执行关系审核或替代。

精确记录入口在没有已保存分页视图时直接请求所选记录，跨页记录也须立即可见；返回身份不符时失败，不替换第一页。用户可“浏览本文件记录”回到同一查询条件下的文件分页，清除链接中的精确定位并保留业务图返回上下文。已有保存视图优先保留其页码和游标。

记录检查区通过已授权的分页业务关系列表反查明确记录绑定，沿用有效案例来源和关系筛选。没有案例时默认仅查当前版本已通过关系，待审范围须明确选择。部分完成、无绑定和读取失败分别显示；拒绝访问时清空结果。点击匹配项进入来源限定的业务节点，原图返回入口独立保留。切换记录中止并清空此前查询，不按名称或虚构几何匹配。

业务图链接可保存`revisionMode: "all" | "current"`；未指定时显示全部历史。当前记录仅在完整、未聚焦的范围载入后，收起同一资料、同一三元组、同一已通过或待审队列内有明确更正指向的前版。不按时间戳猜最新，不替用户解决并行分支，不让待审更正覆盖已通过知识。分页未完、局部对象和精确历史保留全部已载入记录并说明范围；循环或无效指向不隐藏证据。类型与时间筛选在更正选择之后应用，前版仍可精确回查。这是授权查询结果的显示选择，不产生新的审批或权威状态。

保存查询含业务条件时，探索页打开多源问题与证据图。总览明确收起观测明细并显示图中/范围计数，选择对象可展开依据。记录与地图链接保留同一查询，审核状态持续可见；普通查询仍保留资料来源图。中英文使用共享图画布和设计变量。

业务问题图支持按对象类别查看已有关系的两步邻域；它只是图形聚焦，不能改变表格、地图共用的业务查询范围。对象类别与节点选择写入当前查询链接，刷新和返回仍恢复；原文证据默认收起，可逐条展开。时间表单按需展开并显示已应用日期。资料与观点沿用共享语义色，并保留类型文字；小图标签可多行显示，详细证据仍可追溯。
